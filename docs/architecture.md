# Архитектура первого серверного этапа

Браузер открывает HTML/CSS/JavaScript с FastAPI. Тот же адрес обслуживает `/api/*`, поэтому отдельный прокси и настройка CORS не нужны. Обработчики API используют SQLAlchemy; драйвер psycopg подключается к PostgreSQL на `127.0.0.1:54329`. Клиент больше не содержит массива демопредметов или localStorage для истории.

## Основные запросы

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверить приложение и соединение с базой |
| GET | `/api/objects` | Последнее обнаружение каждого предмета |
| GET | `/api/cameras` | Камеры и их параметры |
| GET | `/api/events?camera_id=2&q=рюкзак` | Фильтрация событий |
| POST | `/api/search` | Поиск и запись истории; тело `{"query":"Где мои ключи?"}` |
| GET | `/api/history` | Последние запросы локального пользователя |
| DELETE | `/api/history` | Очистить историю локального пользователя |
| GET | `/api/video-segments/{id}` | Метаданные видеоподтверждения |

Ввод ограничен 300 символами. Пустые запросы отклоняются. SQLAlchemy передаёт данные как параметры SQL-запросов. Для вывода пользовательских строк интерфейс экранирует HTML. Ошибка API показывается в интерфейсе; незаметной подстановки старых демоданных нет.

## Таблицы и соответствие диаграммам

| Таблица | Назначение |
|---|---|
| `users` | Один локальный профиль, без авторизации |
| `locations` | Комнаты |
| `cameras` | Камеры, привязанные к комнатам |
| `object_types` | Виды предметов и словарь поиска |
| `objects` | Экземпляры предметов |
| `event_types` | Типы событий |
| `events` | Обнаружение: предмет, камера, место, время, уверенность, видео |
| `video_segments` | Метаданные синтетического видео; место для будущего файла |
| `search_history` | Текст вопроса, время и число результатов |

Человек (`Person`), траектории и точки траекторий пока не реализованы. История пользовательских вопросов выделена в `search_history`; её не следует смешивать с событиями, полученными из видео. Перед расширением нужно уточнить кратности на исходной ER-диаграмме.

## Локальная база

Скрипт создаёт отдельный кластер внутри `data/postgres`, используя установленный PostgreSQL. Windows-служба не создаётся. Другие кластеры и базы не изменяются. Пароль генерируется в `.env`; временный файл для initdb удаляется после инициализации. Вложенные процессы PostgreSQL запускаются без консольного окна, чтобы закрытие окна установки не останавливало базу.

Альтернатива — `docker compose up -d db` с тем же `.env`. Этот вариант использовать вместо локального кластера: одновременно на одном порту они не работают. Compose хранит данные в отдельном Docker volume, поэтому в этом варианте данные физически находятся в Docker, а не `data/postgres`.

## Развитие

1. Alembic для изменения схемы без потери данных.
2. Загрузка видео, проверка формата/размера, хранение файла, состояния обработки.
3. Отдельный процесс обработки видео, сначала один вид предмета.
4. Настоящие обнаружения и видеофрагменты; измерение качества на тестовых записях.
5. Отслеживание и события взаимодействия с предметами.
6. Свободные запросы через LLM поверх фактов из базы.
7. Вход пользователей, живые камеры и внешнее развёртывание.
