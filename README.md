# Искра — поиск вещей по камерам

Первый серверный этап проекта ТРПО. Интерфейс подключён к Python/FastAPI и настоящей PostgreSQL. Предметы, события, камеры и история запросов хранятся в базе. Видеораспознавание пока не подключено: используются шесть демонстрационных предметов и синтетические анимации.

## Запуск 

1. При первом запуске дважды нажать `Setup.cmd`. Дождаться `Setup complete`.
2. Дважды нажать `Start.cmd`. Оставить окно открытым.
3. Открыть **http://127.0.0.1:8000**.
4. Документация запросов: **http://127.0.0.1:8000/api/docs**.

PowerShell-сценарии не используются. Менять политику выполнения Windows не требуется.

Остановка приложения: Ctrl+C в окне `Start.cmd`. База работает отдельно и сохраняет данные; для её остановки запустить `Stop-Database.cmd`. Повторный `Start.cmd` запустит её снова. Не удалять `data/postgres`: там настоящие данные.

Если приложение уже работает, `Start.cmd` сообщит об этом. Если окно установки показало ошибку, запускать приложение после устранения причины, а не считать установку завершённой.

## Требования

- Windows, Python 3.12+ и PostgreSQL 17+.
- На этом компьютере создана `.venv`, PostgreSQL найден в `C:\Program Files\PostgreSQL\17\bin`.
- Для другого расположения PostgreSQL задать `PG_BIN` в `.env`.
- При переносе на другой компьютер создать окружение: `py -3 -m venv .venv`, затем `Setup.cmd`. Копировать `.venv` между компьютерами не нужно.
- `requirements.lock.txt` фиксирует проверенные версии библиотек. При первой установке требуется интернет.

```text
ТРПО/

  backend/app/           Сервер, модели БД, демонстрационные данные
  tests/                 Проверки API и сохранения данных

```

## Что уже работает

- Загрузка списка камер, предметов и событий из PostgreSQL.
- Поиск по названиям/синонимам предметов и названиям комнат через API.
- Выбор самого свежего обнаружения каждого предмета.
- Фильтрация событий по камере и тексту на сервере.
- Сохранение истории запросов в PostgreSQL, повтор и очистка истории.
- Синтетический плеер с паузой и перемоткой. Метаданные фрагмента приходят с сервера.
- Часовой пояс отображения: Екатеринбург; время в БД хранится с учётом часового пояса.

## Проверки

Из этой папки:

```text
.venv\Scripts\python.exe -m pytest -q
node --check frontend/app.js
```

Автотесты используют отдельную временную SQLite, не рабочую PostgreSQL. Проверяются валидация, поиск, фильтры, выбор последнего обнаружения, повторный старт приложения и сохранение/очистка истории. Реальная PostgreSQL проверяется отдельно через `scripts/smoke_postgres.py`.

## Важно о текущем этапе

Это локальная версия для одного пользователя. Отдельной авторизации, LLM, обработки загруженных файлов, RTSP-потоков и настоящих видеозаписей нет. Демособытия датированы 2 ноября 2026 года. Проценты уверенности — заданные демозначения. Существующая опубликованная демоверсия по прежней ссылке не обновляется при локальной работе.

Сервер и база слушают только `127.0.0.1`. Текущий пользователь PostgreSQL владеет отдельным кластером проекта; это конфигурация разработки. Перед внешним развёртыванием нужны отдельная роль БД с ограниченными правами, авторизация и настройки хранения видео. Пароль из `.env` не публиковать.

Схема таблиц пока создаётся при первом старте через SQLAlchemy. Это не система миграций: перед следующими изменениями схемы добавим Alembic. Существующие таблицы автоматически не перестраиваются.
